## 1. Problem & Hypothesis

### Problem (Verified in Post-H3 Audit)
1. **`Chaos B` Floor Deadlock:** `CollabManager.disconnect_peer()` closes `_ws_client`/`_http_session`, but leaves `floor_state="listening"` and `active_peer` populated (`11_chaos_testing.md`), deadlocking turn-taking on mid-turn drops.
2. **2-Peer Scalar Limit & Dead Wiring:** `CollabManager` only models a single `active_peer` scalar; `Orchestrator._on_collab_hello` is dead code; subsystems (`Singer`, `VTSClient`, `ChessController`) never auto-emit `duet_sync`, `emote_sync`, or `game_move` frames.

### Hypothesis
If we refactor `CollabManager` into a **bounded `N<=4` peer HMAC-SHA256 mesh** with:
1. Deterministic `disconnect_peer()` cleanup (`floor_state="idle"`, `active_peer=None`, lease expiry TTL);
2. Priority-queue floor arbitration (`creator_override > active_speaker > round_robin_peer`) with `±60s` timestamp skew and 1024-nonce LRU replay protection;
3. EventBus-driven auto-emission of `duet_sync`, `emote_sync`, and `game_move` frames;

Then **mid-turn peer drops will produce `0` stuck `floor_state` deadlocks across 50 fault injections, and 3-peer collaborative sessions will maintain `<= 1%` turn-collision rate with `< 20 ms` LAN sync propagation.**

## 2. Minimal Isolated Experimental Design

| Dimension | Baseline (Post-H3) | Treatment (`N<=4` Mesh) |
|---|---|---|
| **Peer Topology** | 2-peer scalar (`active_peer`) | Bounded peer table (`N <= 4`, `peer_id -> state/last_seen`) |
| **Disconnect Recovery** | Leaves `floor_state="listening"` (`Chaos B`) | Resets `floor_state="idle"` + lease TTL (`10s` max hold) |
| **Subsystem Sync** | Inbound-only (`on_hello` dead code) | `EventBus` hooks auto-emit `duet_sync`, `emote_sync`, `game_move` |

### Isolated Procedure
1. Spin up `3` in-process/localhost `CollabManager` instances over loopback WebSockets with `HMAC-SHA256` auth.
2. **Fault Injection (`Chaos B+`):** Inject `50` abrupt `disconnect_peer()` / TCP drop events mid-speech (`floor_state="listening"`) and assert immediate recovery to `"idle"`.
3. **30-Minute 3-Peer Soak:** Run simulated chat + karaoke `duet_sync` + `emote_sync` + chess `game_move` exchanges; measure turn-collision rate, frame propagation latency, and memory stability.

## 3. Go / No-Go Gate Criteria

| Metric | Baseline (Observed) | Go Threshold (Target Estimate) |
|---|---|---|
| Stuck `floor_state` after 50 peer drops | Fails on 1st drop (`Chaos B`) | **`0 / 50` deadlocks (`100%` reset to `"idle"`)** |
| LAN sync frame propagation (`p95`) | N/A (unwired) | **`<= 20 ms`** |
| 3-peer turn-collision rate | N/A (2-peer only) | **`<= 1.0%`** |
| Replay / SSRF / `NaN` rejection | Verified (`H0`–`H3`) | **`100%` preserved** |

**Rollback:** Gate N-peer mode behind `collab.mesh_enabled: false` (default) so 2-peer hardened mode remains the safe fallback.
