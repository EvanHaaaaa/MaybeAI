## 1. Problem & Hypothesis

### Problem (Verified in Post-H3 Audit)
1. **Main Event-Loop Slow Callbacks:** Full-suite `-W default` runs exhibit `asyncio` slow callbacks (`0.109s–0.282s`) from synchronous disk/engine/audio initialization and ML work sharing the FastAPI event loop.
2. **Unverified Local Neural Stack:** `faster-whisper`, `kokoro_onnx`, and `silero-vad` are absent from `.venv` (`03_realtime_audio.md`). Running them in-process alongside FastAPI `/ws` fan-out (`0.074–2.159 ms`/broadcast) risks GIL contention, VRAM OOMs crashing the main server, and `barge_in` jitter.

### Hypothesis
If we isolate local ML inference (`Silero-VAD`, `faster-whisper` INT8, `kokoro-onnx`, `FastEmbed`, and optional local VLM) inside a **Dedicated Inference Worker subprocess** communicating over bounded async IPC queues (length-prefixed JSON-RPC + binary PCM frames):
1. Main FastAPI/EventBus process stays pure async I/O (`0` ML model weights in main RSS/VRAM);
2. Worker supports clean `cancel(utterance_id)` on `barge_in()` and automatic supervisor restart (`<= 3s`) on OOM/crash without dropping `/ws` browser/OBS clients;

Then **main event-loop callbacks `> 50 ms` during concurrent STT+TTS+Embedding bursts will drop to `0`, `/ws` ack p99 will stay `<= 15 ms`, and worker crashes will recover in `<= 3 s` with `0` dropped WebSocket clients.**

## 2. Minimal Isolated Experimental Design

| Dimension | Baseline (In-Process) | Treatment (Dedicated Inference Worker) |
|---|---|---|
| **Process Boundary** | Single Python process (`run.py`) | `run.py` (FastAPI/EventBus) + `inference_worker.py` subprocess |
| **IPC Transport** | Direct `await` / `asyncio.to_thread` | Bounded async pipe/stdio or localhost Unix/TCP socket (`maxsize=64`) |
| **Crash Blast Radius** | Native ONNX/CUDA OOM kills entire server | Supervisor restarts worker in `<= 3 s`; `/ws` & `Edge-TTS` fallback stay alive |
| **Cancellation** | `CancelledError` inside shared loop | Explicit `cancel_utterance` IPC frame + `barge_in` flush |

### Isolated Procedure
1. Build a standalone `inference_worker.py` prototype hosting `FastEmbed` (or mock CPU/ONNX load simulating 200ms STT + 150ms TTS + 15ms embedding).
2. Connect a test harness simulating `100` concurrent `/ws` listeners receiving `avatar_state` ticks at `20 Hz` while firing `20` STT+TTS+Embedding bursts and `10` mid-stream `barge_in` cancellations.
3. Inject `SIGKILL` into `inference_worker.py` mid-utterance and measure supervisor restart time, `/ws` client survival (`100%`), and fallback continuity.

## 3. Go / No-Go Gate Criteria

| Metric | Baseline (Observed) | Go Threshold (Target Estimate) |
|---|---|---|
| Main-loop slow callbacks (`> 50 ms`) | `0.109s–0.282s` observed (`-W default`) | **`0` callbacks `> 50 ms`** |
| `/ws` ack p99 during STT+TTS burst | Vulnerable to GIL/sync stalls | **`<= 15 ms`** |
| `barge_in` cancellation latency | `<= 50 ms` target | **`<= 50 ms` (`0` post-cancel audio frames)** |
| Worker crash recovery (`SIGKILL`) | Kills entire process | **`<= 3 s` restart; `0` dropped `/ws` clients** |
| Worker base RSS overhead | `0 MB` (shared) | **`<= 150 MB` Python base (excl. model weights)** |

**Rollback:** Config flag `system.inference_worker_enabled: false` falls back to existing in-process `asyncio.to_thread` + cloud `Edge-TTS` / `OpenAI` providers.
