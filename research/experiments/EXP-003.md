**Status:** Proposed (Ready for Horizon 2 Execution)

## 1. Problem & Hypothesis

### Problem
MaybeAI's autonomous mission loop (`AutonomousMissionExecutor` + `GoalEngine` + `MinecraftController`) currently fails under real-world conditions:
1. **Unreachable `COMPLETED` state (`[COG-CRIT-001]`):** `Goal.recalculate_progress()` includes `REPLANNED` subtasks in its denominator, locking any replanned goal in `in_progress` forever.
2. **Infinite 25s replanning loop (`[COG-CRIT-002]`):** Neither `GoalEngine`, `StrategyReplanner`, nor `AutonomousMissionExecutor` enforces `max_attempts`, causing unbounded `goals.json`/`agenda.md` growth and mood/TTS spam.
3. **0ms polling vs. fabricated progress (`[COG-HIGH-001]`):** Connected Minecraft tasks check `get_inventory_count()` 0ms after `toggle_wander()`, guaranteeing failure; disconnected/unwired tasks fabricate `simulated: True` progress.
4. **Silent Node.js bridge death (`[GAME-CRIT-002]`):** `MinecraftController` leaves `connection_status="connected"` when `bot.js` crashes, and `bot.js` leaks `setInterval` timers and swallows `uncaughtException`.

### Hypothesis
If we:
1. Refactor `Goal.recalculate_progress()` to exclude `REPLANNED` subtasks and enforce a bounded FSM (`MAX_REPLAN_ATTEMPTS = 3` -> `FAILED`/`ABANDONED` -> `autonomous_select_next_activity()`);
2. Separate `verified_execution` from `simulated` commentary and replace 0ms inline Minecraft polling with **cross-tick `baseline_count` + `mc_telemetry` ACK window** (plus `approval_timeout_sec` TTL for `[COG-MED-001]`);
3. Add a bounded exponential-backoff Node.js bridge supervisor + `bot.js` timer cleanup and `EADDRINUSE` exit handling;

Then **infinite replan loops will drop to `0`, false offline mission completions will drop to `0%`, and a 2-hour fault-injected Minecraft soak test will maintain `>= 95%` state accuracy with `< 10 s` bridge crash recovery.**

## 2. Experimental Design & Matrix

| Dimension | Baseline (Control) | Treatment (Bounded FSM + Telemetry ACK) |
|---|---|---|
| **Progress Math** | Includes `REPLANNED` in denominator | Excludes `REPLANNED` subtasks |
| **Replan Bound** | Unbounded (`attempts` ignored) | `MAX_REPLAN_ATTEMPTS = 3`, then `FAILED` + goal pivot |
| **MC Verification** | 0ms inline `get_inventory_count()` | Cross-tick `baseline_count` snapshot + `mc_telemetry` delta event (`>= 1` tick or ACK) |
| **Disconnected Mode** | Credits `simulated: True` progress | Pauses/skips progress credit unless `allow_simulated_progress=True` |
| **Bridge Supervision** | None (`connection_status` stays `"connected"`) | `_listen_bridge()` `finally` resets state + bounded backoff restart (`1s -> 2s -> 4s -> 15s max`) |
| **Approval Gate** | Infinite block | `approval_timeout_sec = 120` auto-expiry + `goal_id` validation |

### Fault-Injection Scenarios (`MaybeAI-Agency-Fault-Bench-v1`)
1. **Scenario F1 (Single Failure + Recovery):** Subtask 1 fails once, replans, and succeeds on `[Plan B]`. Verify goal reaches `COMPLETED`.
2. **Scenario F2 (Persistent Impossible Goal):** Subtask fails 5 consecutive ticks (`observed_delta = 0`). Verify replanning halts at attempt `3`, marks goal `FAILED`, pivots to next viable goal, and `goals.json` size stays bounded.
3. **Scenario F3 (Delayed Real Telemetry):** Mineflayer gathers wood `8 s` after command dispatch. Verify 0ms false failure is eliminated and delta is credited on next telemetry/tick.
4. **Scenario F4 (Disconnected Guard):** `MinecraftController.is_connected == False`. Verify `0` Minecraft progress credits are awarded.
5. **Scenario F5 (Bridge Crash & Timer Leak):** Send `SIGKILL` to `bot.js` mid-mission and reconnect 3 times. Verify `connection_status` transitions to `"disconnected"` within `1 s`, auto-recovers within `10 s`, and `bot.js` active `setInterval` count stays `<= 1` per timer type.

## 3. Procedure

1. Implement the treatment FSM, `baseline_count` tracker, and bridge supervisor in an isolated test branch/worktree.
2. Execute unit/integration tests for Scenarios F1–F4 deterministically via `unittest`.
3. Execute Scenario F5 against a local Mineflayer test server (or mock WS bridge + real `node bot.js` process) in a **2-hour soak test** with periodic fault injection every 15 minutes.
4. Log `goals.json` file size, `MoodEngine` annoyance trajectory, `mc_telemetry` vs `minecraft_state` WS message rate (`[GAME-MED-003]`), and recovery latency.
