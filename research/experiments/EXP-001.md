## 1. Problem & Hypothesis

### Problem
MaybeAI's current voice pipeline suffers from four verified defects:
1. **Post-barge-in side effects (`[AUDIO-CRIT-001]`):** `TTSEngine.speak_stream()` suppresses `asyncio.CancelledError` when `_stop_requested=True`, allowing `_execute_interaction()` to emit `ai_response`, Minecraft chat, and Discord replies after `voice_barge_in`.
2. **Synthetic square-wave lip-sync & browser collision (`[AUDIO-CRIT-002]`):** `TTSEngine._play_and_lipsync()` emits an 80ms `0.95`/`0.50` square wave that flaps past short utterances (`max(1.0, words / 2.6)`) and overwrites browser `AnalyserNode` RMS in `output_mode="both"`.
3. **WS receive-loop blocking (`[AUDIO-HIGH-001]`):** `run.py:1544` awaits `orchestrator.process_voice_chunk()` -> `transcribe_wav_bytes()`, blocking `barge_in` and new mic frames for `150ms–30s`.
4. **Disk & TLS overhead (`[AUDIO-HIGH-004]`, `[PERF-MED-002]`):** Double `.mp3` write/read roundtrips per sentence and unpooled `aiohttp.ClientSession` calls.

### Hypothesis
If we:
1. Replace `EnergyVAD` (`0.02` RMS) with **Silero-VAD (ONNX)** on 512-sample (32ms) frames and offload `faster-whisper` transcription to a bounded async worker queue;
2. Stream `Edge-TTS` / `Kokoro-82M` (`kokoro-onnx`) in memory with a persistent `aiohttp.ClientSession` and strict `CancelledError` propagation;
3. Compute a 25ms PCM/RMS amplitude envelope on the server for `VTSClient` while arbitrating `targetMouthOpen` ownership on the browser (`isPlayingAudioQueue` guard);

Then **end-to-end voice TTFA will drop below `700 ms` (local Kokoro) / `1100 ms` (cloud Edge-TTS), `/ws` receive-loop p99 latency during STT will stay `< 15 ms`, VAD false-triggers under noise will drop `< 2%`, and barge-in will achieve `0` post-cancel emissions.**

## 2. Experimental Design & Matrix

| Variant | VAD | STT Execution | TTS Provider | Lip-Sync Source |
|---|---|---|---|---|
| **Baseline (Control)** | `EnergyVAD` (`0.02`) | Inline `await transcribe_wav_bytes()` | `Edge-TTS` (disk roundtrip) | 80ms square wave (`0.95`/`0.50`) |
| **Variant A (Cloud-Safe)** | `Silero-VAD` (ONNX CPU) | Async worker queue (`faster-whisper` `base` INT8) | `Edge-TTS` (`BytesIO` + pooled session) | Server PCM/RMS envelope + Browser `isPlayingAudioQueue` guard |
| **Variant B (Local-First)** | `Silero-VAD` (ONNX CPU) | Async worker queue (`faster-whisper` `base` INT8) | `Kokoro-82M` (`kokoro-onnx` CPU/CUDA, WAV in-memory) | Server PCM/RMS envelope + Browser `isPlayingAudioQueue` guard |

### Independent Variables
- Audio environment: clean speech vs. speech + BGM/keyboard noise (`MaybeAI-Voice-Bench-v1`, 50 utterances).
- `output_mode`: `"browser"` vs. `"both"`.
- Forced barge-in injection at `t = 250 ms`, `t = 600 ms`, and `t = 1200 ms` after TTS start.

### Dependent Metrics
1. **TTFA (ms):** Time from `speech_ended` VAD event to first `audio_chunk` received by browser / played by `pygame`.
2. **WS Loop Stall (ms):** Max & p99 delay of `barge_in` / `voice_chunk_ack` processing while STT is running.
3. **VAD False-Trigger Rate (%):** Non-speech noise bursts falsely triggering `speech_started` / `barge_in`.
4. **Lip-Sync Envelope Correlation ($r$):** Pearson correlation between `VTSClient` `mouth_open` stream and true audio RMS envelope (`25 ms` window).
5. **Barge-In Leak Count:** Number of `ai_response`, Minecraft, Discord, or `mouth_open > 0` events emitted after `voice_barge_in`, plus leftover temp files.
6. **Resource Footprint:** Peak RSS RAM (MB), VRAM (MB), and CPU % during 15-minute continuous conversation.

## 3. Procedure

1. **Pre-requisite Fixes (Safety Guard):** Ensure `[AUDIO-CRIT-001]` (`CancelledError` re-raise), `[AUDIO-HIGH-002]` (`singer.stop()` in `barge_in()`), and `[AUDIO-HIGH-003]` (`fallback_voice` + WAV/MP3 MIME detection) are applied in the experiment branch.
2. **Instrument Timing Probes:** Record monotonic timestamps (`time.perf_counter()`) at: `vad_speech_end`, `stt_start`, `stt_end`, `llm_first_token`, `sentence_ready`, `tts_first_bytes`, `ws_audio_sent`, `barge_in_received`, `audio_stopped`.
3. **Run `MaybeAI-Voice-Bench-v1`:** Execute Baseline, Variant A, and Variant B across 50 utterances + 20 forced barge-in interrupts.
4. **Run Lip-Sync Sync Test:** Play 10 short (2-word) and 10 long (20-word) utterances in `output_mode="both"` and log `VTSClient` `MouthOpen` vs. `web/overlay.js` `targetMouthOpen` frames.
5. **Run 15-Minute Soak:** Stream continuous noise + intermittent speech to verify zero memory growth, zero temp-file leaks, and stable `aiohttp` connection reuse.

## 4. Go / No-Go Gate Criteria

| Metric | Baseline (Observed/Audit) | Go Threshold (Required to Promote) |
|---|---|---|
| Post-barge-in side-effect leaks | `>0` (`[AUDIO-CRIT-001]`) | **`0` across 20/20 forced interrupts** |
| Temp audio file leftovers | `0` (verified in Chaos B) | **`0` leftovers** |
| WS `/ws` ack p99 during STT | `150–3000+ ms` (blocked) | **`<= 15 ms`** |
| Local TTFA (Variant B: Kokoro) | N/A | **`<= 700 ms` p50, `<= 1000 ms` p95** |
| Cloud TTFA (Variant A: Edge-TTS) | ~900–1500 ms | **`<= 1100 ms` p50** |
| VAD False-Trigger Rate (noise) | Unbounded (static `0.02`) | **`<= 2.0%`** |
| Lip-sync RMS correlation ($r$) | ~0.0 (square wave) | **`>= 0.85`**, `0` post-speech flapping |
| VRAM footprint (Profile B) | N/A | **`<= 2.0 GB` combined (`faster-whisper` + `kokoro-onnx`)** |

**Rollback / Fallback:** If `kokoro-onnx` or `faster-whisper` exceeds Profile A/B CPU or VRAM limits, keep `Silero-VAD` + async STT worker + in-memory `Edge-TTS` (Variant A) as default and retain `kokoro-onnx` as opt-in `tts-local` extra.
